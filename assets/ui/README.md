# Original antique interface artwork

Created on 2026-10-22 with the built-in image-generation tool. These are original generated assets, not extracted game textures or downloaded packs. No generation service, model, editor, or network connection is needed to build or run the game.

- `antique-frame.png`: 1254 x 1254, bronze acanthus relief around dark worn leather. `game/UiSkin.h` supplies the same nine-slice boundaries to DirectX 11 and GDI+. Corner relief stays fixed in size; straight rails and the leather centre stretch.
- `chapter-hall.png`: 1672 x 941, illustrated stone chapter hall. Launcher and character selection use it as a backdrop; the selected champion remains a live rotating 3D model. This is menu concept artwork, not a screenshot or a new playable location.
- `equipment-icons.png`: 1254 x 1254, 25 illustrated cells. Rows contain eleven class weapon forms, potion/clothing/armor and dash/heal/heavy-strike motifs. Explicit cell bounds in `PaintedIcon` account for the taller final row. The images are illustrative; their fine ornament does not claim an exact match with prototype 3D equipment.

All text, controls, quantities, cooldowns, character information and selection remain runtime content. No labels are baked into the images. `UiArtwork.rc` embeds all three in client executables; `launcher/Launcher.rc` embeds just its two required assets.

The renderer decodes resources once through WIC, caps frame/icons to 1024 square and the hall to 1536 x 864, generates mipmaps and discards CPU decode buffers. Artwork occupies 18,262,592 GPU bytes; with the existing font and map, the UI occupies 19,791,764 bytes (under the tested 20 MiB cap). Textures remain bound in the HUD batch, with no per-panel texture upload or extra render pass. Artwork dimensions and byte counts exclude driver allocation overhead and GDI+ launcher memory.

## Reference research

The user's supplied equipment/bag screenshot establishes the primary target: sculpted, dimensional metal; densely tooled dark interiors; bright illustrated objects; compact readable controls. The previous implementation used green gradients, repeated wire decorations and symbolic item drawings, which did not achieve that material quality.

- [Allods official quick-start guide](https://allods.ru/about.php?show=quickstart): character creation/selection workflow and equipment/action-panel context. Its inline full-size image endpoints were unavailable to the research browser; the user's supplied screenshot remains the direct visual reference.
- [WoW Classic character-selection captures](https://www.windowscentral.com/things-i-miss-about-wow-classic-and-things-i-dont): a staged hero against a scenic environment, separate roster controls and a strong primary entry button.

The new art uses an original bronze/burgundy/leather palette. It does not reproduce either game's logo, frame assets or world locations. This checkpoint improves UI materials; production character anatomy, environment textures and fully distinct spell illustration libraries remain separate work.
