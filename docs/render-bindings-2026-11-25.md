# Render resource ownership and shader interfaces — 2026-11-25

## Result

Every existing renderer pass now uses one immediate-context owner for vertex
and pixel shader resources/samplers and render/depth targets. Previously each
pass manually disconnected a few known slots; aliases in another slot or stage
could rely on DX11 silently nulling them. That implicit mutation also makes a
binding cache unreliable. The new owner resolves overlapping reads explicitly
before installing writable outputs and rejects a conflicting new read before
changing any state.

This is engine work. It does not restyle the scene, change spell effects or
alter models, faces, gameplay, UI or assets. The existing render output is the
acceptance baseline.

## Ownership rules

- `engine/RenderBindings.*` owns VS/PS SRVs and samplers, RTVs and the DSV.
  All existing passes, including shadows, cloud lighting, portraits and
  postprocessing, route these operations through it.
- Conflicts use the underlying resource, mip interval, array-slice interval and
  depth/stencil aspect, rather than comparing view pointers. Read-only depth
  remains sampleable while writable stencil is protected independently.
- A target change disconnects overlapping inputs in both shader stages before
  calling `OMSetRenderTargets`. Disjoint mips and slices retain their bindings.
  Read requests conflicting with current writable outputs are rejected as a
  caller error; they do not silently discard the active output.
- Invalid slot ranges, incompatible target sizes/sample counts, duplicate
  output subresources and unsupported view dimensions fail before mutation.
  Resources and samplers must belong to the attached device. A stale view from
  a previous device cannot enter a reconstructed renderer.
- Changed batches are validated in full before submission. Failed batches
  preserve native state. Identical requests skip the driver call, including
  resource-description work. Changed spans are submitted together.
- `Clear()` unbinds and releases tracked references before resize or teardown.
  Reattachment clears the previous context before adopting the new one.
  A real swap-chain resize test verifies that the owner retains no hidden
  back-buffer reference. Deferred contexts are rejected.
- Per-frame counters expose requests, actual binding calls, skipped requests,
  automatic alias unbinds and rejections. Benchmark reports include these
  counters; they are not FPS or GPU-time savings estimates.

Supported views cover current buffer reads and 2D/array/MSAA/cube texture
reads, with 2D/array/MSAA render/depth outputs. This is not a general render
graph or a multithreaded context. Geometry/compute stages, UAVs, 1D/3D views,
copy/upload hazards and upload completion ownership remain outside this layer.
The pressure copy retains its explicit disconnect. Do not change owned state
directly through the native context or call `ClearState` behind the owner's
back. Other pipeline state remains managed by the renderer.

## CPU/GPU contracts

`engine/ShaderInterface.h` supplies named texture/sampler registers and vertex
descriptors built from the real C++ vertex, instance and skin-influence types.
The runtime input layouts and build-time reflection use the same descriptors.
Reflection now validates semantic/index, component type/count, resource kind,
dimension, register, texture return type, sampler comparison mode and the
structured palette row stride. The earlier eight constant-buffer contracts
remain active.

`engine/SkinPaletteLayout.h` supplies row addresses to both C++ and the embedded
HLSL. Compile-time checks tie those addresses to actual palette offsets, matrix
and dual-quaternion sizes, and total row count. This removes separately edited
numeric addresses without changing skinning or animation behavior.

`ShaderContractTests` compiles all 19 entries, covers eight constant buffers,
21 SRVs and three samplers, and rejects 17 deliberately broken interfaces.
Validation runs before generated bytecode is published, with no launch-time
reflection or shader compilation. The standalone shader script now expands
all included fragments and the shared row definitions and checks all 19
entries; its bytecode comparison previously omitted the later postprocessing
entries.

## Verification

Release acceptance initially passed all 12 selected suites in 80.32 seconds:
RenderBindingsTests, GraphicsLifecycleTests, ShaderContractTests,
GpuFrameQueueTests, SurfaceStorageTests, BenchmarkStatsTests, SkinningTests,
HandSkinningTests, ShadowTests, PressureEffectsTests, SpellVolumeTests and
InterfaceTests. Final Release acceptance, after device-ownership and noncopyable
owner changes, passed the same **12/12 suites in 73.18 seconds**. Final Visual
Studio Debug acceptance passed **12/12 in 131.31 seconds** (the earlier run
took 154.39 seconds). Both public `RPGNative.exe` builds are rebuilt. This is
focused engine acceptance, not a run of all 95 registered project suites.

The native binding tests query actual VS/PS/OM state, not a CPU imitation. They
exercise alias views, the last legal slots, disjoint mips/slices, multi-slot
rollback, writable/read-only depth and stencil, sampler caching, real
ResizeBuffers, two devices and context replacement. The lifecycle tests still
exercise full renderer reconstruction, portrait restoration and unchanged
session/camera data.

All **43 pre-change PNG SHA-256 hashes matched** after the initial acceptance
run: hand skinning, shadows, pressure, spell volumes and renderer recovery.
The restored world/character capture was also inspected. The lifecycle fixture
reported 71 binding requests, 37 driver calls, 36 skipped requests and two
automatic alias unbinds per frame. Calls can exceed requests minus skips because
one transition may explicitly clear inputs in multiple stages. The final
Release rerun regenerated all 43 images and again matched every baseline hash.

The rebuilt game also completed its actual hidden 1280x720 spawn benchmark
(90 warmup plus 240 measured frames, NVIDIA RTX 4060). Its final frame reported
55 requests, 21 driver binding calls, 37 skipped requests and three alias
unbinds. The report is `build-ninja-release/bindings-benchmark.txt`; this verifies
the diagnostics in the game executable and does not establish an interactive
FPS improvement or a comparison with another revision.

The DX11 debug layer is unavailable on this machine. The dedicated test reports
this explicitly and still runs on the native hardware device. A Debug build is
not evidence of driver-layer validation. No driver reset, system modification
or download was performed; long visible play remains manual acceptance.
