# Native architecture

## Current boundaries

The project is single-player today. Keep one map and its gameplay loop testable before expanding it. Allods Online is the primary design reference; the current art is a procedural stylized prototype.

| Component | Responsibility | Dependencies |
| --- | --- | --- |
| `WorldMap` | Map bounds, solid props, areas, traversal queries, navigation routes | C++ standard library |
| `Inventory` | Canonical item catalog, bag stacks, worn slots, transactional item commands and serialization | C++ standard library |
| `Trade` | Offer/sale prices and Simulation purchase, sell, buyback, range and stock rules | `Inventory`, `Simulation`, C++ standard library |

| `TerrainSurface` | Generate a compact dirt/paving weight texture from shared world routes | `WorldMap`, C++ standard library |
| `Game` | Translate local input, update simulation, camera, interface actions, save-file I/O | Simulation, input, renderer, Windows file replacement |
| `Interface` / `InterfaceState` | Scaled layouts, hit regions, HUD/panels, validated item commands | Renderer, simulation |
| `CharacterView` / `MapArtwork` | Shared dressed character, generated terrain/landmark illustration | Renderer, world data |
| `CharacterPose` | Fixed-length local arm/leg joints and weapon direction for walking and strikes | DirectXMath, C++ standard library |
| `Motion` | Analytic speed ramps, shortest-arc turns, travel-driven pose filters and camera boom response | C++ standard library |
| `Animation` | Bounded breathing, air/landing, recoil and travel channels, advanced only during updates | C++ standard library, `Motion` |
| `CombatEffects` | Fixed pools of blade histories and impact bursts, driven by confirmed transient events | Simulation events, DirectXMath, `Renderer` |
| `Geometry` | Reusable indexed meshes, generated material layers, frustum tests | DirectXMath, C++ standard library |

| `Engine` / `Win32Window` | Window lifecycle, frame timing, pause on focus loss, resize | Win32, game, renderer |

`MediterraneanSimulation` is a separate library with no Windows or DirectX includes. Tests link that library rather than recompiling a separate copy of the gameplay implementation. Rendering consumes state and does not award loot or apply damage.

`Progression.cpp` implements `Simulation`'s derived XP/level rules, objective presentation data, bounded combat feedback, death recovery and sparring lifecycle. The renderer projects event positions onto the screen; it never resolves combat. Enemy kind controls health, windup, damage, and recovery. Windup facing is committed in the simulation and shared with the visible ground cone. The transient trainer is separate from the campaign enemy collection, preventing practice kills from changing XP, quests or loot. `TargetActor()` resolves either target for the UI and ability checks.

Player/enemy `movementDistance` records successful locomotion travel in the latest simulation update; enemy travel includes bounded separation, while player travel excludes dash and respawn. It resets before early returns and is omitted from saves, along with acceleration state. Speed ramps and constant-gravity jumping are integrated analytically at the bounded simulation step. No player input stops physical movement immediately; only the visible feet settle. Blocked movement cannot bank full running speed. Enemies consume reached path points within the same step, turn toward their route before moving, ease into arrival and refresh exhausted paths. An unobstructed destination updates every frame; obstructed routes retain their bounded A* refresh. Stopping short of the player requires clear line of sight, so close opponents on opposite sides of a trunk still navigate around it. A swing starts only when facing is within 0.1 radians of the player and freezes that heading throughout its original windup.

`Game` keeps one `motion::Actor` per campaign enemy, one trainer pose and a player pose. Distance drives gait phase; the gait filter integrates the sine target throughout each travel interval instead of sampling only its endpoint. Constant-speed walking therefore retains the same phase/amplitude at 30/60/144 Hz. Body lift uses squared gait to avoid a sharp vertical cusp at neutral. Gait uses the exact critically damped response to the moving sine target, retaining both position and velocity when travel changes or stops. Player turns follow a critically damped shortest-arc target; strike poses use the same second-order response with a faster settling rate. These filters carry velocity across target changes and clear it on reset. Enemy presentation uses simulation facing exactly so its cone remains truthful. `ExecuteCommand` advances these filters once; `Render` only reads them. Reset/load/respawn clear old motion; a loaded committed enemy swing reconstructs its pose. Fatal damage clears the player's strike feedback and visible pose.

`Simulation` emits at most sixteen `CombatVisualEvent` records in one update, after attack validation or enemy windup completion. Every update clears the count before early returns; load/restart construct clean transient state. These records never enter saves or combat calculations. `Game::ExecuteCommand` ages/emits into `CombatEffects`, then samples the actual posed blade through `CharacterPose::WeaponPoint`. Eight trail slots hold up to 32 blade samples each plus the attack origin/facing for a 0.32-second crescent; Heavy Strike adds a delayed counter-sweep. Thirty-two impact slots use analytical spark/mote trajectories lasting up to 0.48 seconds. Death cancels trails, weapon discontinuities over two units cancel the entire trail and crescent, and normal reset/load/respawn clear all slots. Rendering is read-only. Effect geometry queues separately from opaque instances, then flushes after the world and before HUD/portrait depth changes. The texture-free shader provides soft ribbon halos, bright cores, tapered streaks and derivative-filtered shock rings. Additive blending uses read-only depth and the existing dynamic HUD vertex buffer. The 6,144-vertex frame limit drops excess cosmetic quads without increasing allocation or failing gameplay.

Camera targets ease during local mouse orbit, wheel zoom and jump/landing. WASD uses the predicted filtered heading of that same frame, not the pending input target. Gesture cancellation and central-panel/drag capture discard pending orbit by anchoring its target to the current view. The horizontal target stays on the authoritative player to avoid camera lag during dodges. Obstruction queries use the filtered height/orientation and cover both current and requested boom lengths. Geometry retracts the boom immediately; recovery waits for 100 ms of continuous clearance, then eases outward. An inward zoom still responds during that delay. `SetCameraOrbit` remains an immediate tool/capture placement API. Filters add no GPU resources or per-frame allocations and do not change save version 6.

## Rules to preserve

`WorldMap::SurfaceAt` supplies normalized dirt/paving weights for ten authored trail segments and the plaza/training/anchor clearings. `TerrainSurface` rasterizes these into a 256-square RGBA8 texture with mipmaps; the ground shader samples it while `MapArtwork` uses the same world query directly. Deterministic ground cover is built once per map, bounded to 180 instances and 18 shrubs, and excluded from routes, services, solid props and the arena. Grass/shrubs/verge stones are decorative; they do not change collision or save version 6. Dock bounds are shared by world drawing, artwork and cover placement, and tested against solid props.

Folded leaf surfaces and grass blades share startup meshes and the existing leaf material. Separate back faces provide visible undersides without alpha blending or sorting. Trees and shrubs cast shadows; small grass clumps receive lighting/shadows but do not cast. The new ground texture adds 349,524 bytes including mipmaps to the renderer's material/shadow resource count.

Each existing building has a `BuildingRole`; it changes presentation without changing footprints or save data. `LandmarkView` draws the homestead, watch hall, storehouse and training hall, including their windows, trim, crests and emissive lanterns. `BuildingStyle` provides the same roof palette to the atlas. Shared barrel, arch, canopy and beveled masonry meshes are generated once and instanced. Lanterns use emissive material, without adding point lights. These buildings remain exterior-only scenery.

Supply-stall camera queries distinguish the solid counter, two uprights, upper braces and bowed cloth. Open space above the counter and sky above the awning remain clear. The normal merchant camera has a regression against collapsing into the player. Building camera depth includes the new gable decorations; navigation still uses the original walls and counter. GeometryTests checks canopy bounds/clearance and the arch opening; NavigationTests exercises canopy, posts, open bay, above-roof and ordinary merchant/gable camera paths.

- Change solid map geometry through `WorldMap`; movement, navigation, camera queries, map UI, and world presentation should agree about it.
- Use `Command` to express player intent. Validate movement, target range, cooldowns, loot eligibility, and equipment ownership inside the simulation.
- Enemy IDs are stable across save/load; vector indexes are currently local lookup details, not a future network identity contract.
- Loading validates into a candidate simulation and replaces current state only on success. Version 6 stores `SHOP` purchase counts, nine `BUYBACK` item counts, six-slot `GEAR` and exact `BAG` blocks. Reject unknown IDs, incompatible slots, duplicate unique gear, invalid stacks, impossible stock and inconsistent ownership or gold. Player inventory plus merchant-held gear must equal earned/purchased unique items. Gold equals campaign income minus original purchases plus the value of merchant-held items. This bounded ledger needs no accumulating transaction history. Version 5 retains all six slots, purchases and cells with empty buyback; version 4 reads four slots with empty head/off-hand slots; versions 1–3 migrate their old inventory, with proportional captain health for versions 1/2. Actors in old saves overlapping the newly solid counter move to its nearest free edge; all other position checks remain strict.
- Splitting validates the source item, amount and empty destination before mutating either stack. Selected UI state includes a bag index, and item events retain that source through selection/right-click. Selling and drinking validate the exact cell; stale actions do not consume an alternative stack. Only Q requests the first available potion stack. Trade commands validate eligibility, ownership, gold and capacity inside the simulation before changing inventory, merchant holdings and gold.
- XP and earned item entitlements derive from persistent kills/quest completion. Actual item location is the player inventory or buyback. Damage and protection derive from the canonical catalog and currently worn slots. Unequipping or selling ward armor cannot remove earned XP. Respawn retains dead enemies and claimed rewards; only explicit restart resets the campaign.
- Inventory commands carry source/destination indices and the expected item. Validate them at application time so sorting or hotkey swaps cannot turn a stale drag into a different action. Add rewards atomically; full bags must not consume quest or loot credit. Worn items have a single location and never duplicate in the bag.
- Trade UI sends an offer index through `Command::purchase` or an item/source through `Command::trade`. Simulation validates each transaction before committing item/charge/holdings. `GoldSpent` derives from bounded purchase receipts; `BuybackValue` derives from bounded merchant holdings. Respawn retains both, restart clears both. Prices/stock come from one catalog used by the UI and simulation. Shop and portrait orientation are transient presentation state.
- Sparring uses ordinary combat rules but clamps lethal damage to 1 HP and ends. It grants no rewards and refunds no resources. The opponent, round clock and result reset on load; current health, potions and cooldowns remain durable.
- Feedback events are bounded to 24 with a 1.5-second lifetime. Paths, feedback, and unfinished anchor channels are transient; committed enemy swings are durable.
- Navigation paths and presentation state are transient. Paths are rebuilt after loading.
- Keep tests focused on outcomes: reachable routes with collision clearance, valid combat, exactly-once rewards, and persistent state.

Input polling produces an `Input::Frame`; the same transition code processes sampled frames in the hidden client integration tests. Panel/HUD/load transitions invalidate previous hit regions, and pointer dispatch checks rendered panel state and dimensions. Camera orbit belongs to the right-button gesture that began over the world; crossing from UI into the world cannot transfer that gesture to the camera. Engine focus/resize/fullscreen cancellation resets both item dragging and orbit ownership.

Game also cancels and invalidates input before dispatch on an F11 press, since Engine applies the window transition after Game updates. This prevents a release on the same frame from committing a drop first. Defeat closes the central panel and cancels gestures to expose recovery; Enter bypasses central-panel command capture only while defeated and uses normal progress-preserving respawn.

## Future MMO considerations

This separation makes gameplay code reusable, but the project is not network-ready. A future server will need a fixed authoritative tick, sequenced per-player commands, validated entity ownership, state replication, interest management, durable persistence, and reconciliation. Current timing is local and frame-based with a bounded delta. Same-build command replay tests do not establish determinism across platforms or compiler versions.

Do not add transport code, speculative distributed services, or extra maps merely to anticipate that future. First validate this map, document gameplay rules, and profile the real workload.

## Validation

`-Test` runs thirteen suites: combat effects, animation, shadow, motion, interface, geometry, simulation, navigation, inventory, combat, progression, training and trade. The campaign test drives both quests; inventory/training/trade tests verify persistent equipment, purchases, armor and repeatable encounters without farming. GeometryTests checks fixed limb lengths, joint validity and clearance across walking/strike poses. `-SmokeTest` captures four scenarios at three sizes plus five interface panels, combined character/bag, inspection views, fifteen extra veteran outfit/training/shop/buyback views, eight close-up poses and seven environment views, plus six animation-layer and four live jump views, totaling 132 images per configuration. Tests load snapshots in memory without replacing player saves. Interactive input and feel still need the manual checklist. Generated captures and player saves remain ignored; small authored render fixtures live in `tests/fixtures`.

The build helper supports Visual Studio and Ninja in separate output directories. Ninja bootstraps MSVC in a child process, leaving machine settings untouched. `cmake/DetectMsvcIncludes.cmake` probes raw localized `/showIncludes` output to preserve Ninja header dependencies when CMake's automatic decoding mangles the prefix. Work remains uncommitted unless explicitly requested.

Graphics generation, allocations, culling and before/after measurements are documented in [graphics.md](graphics.md). Materials and indexed meshes are created once; transforms are grouped by mesh for a bounded instance upload. Each object receives a three-bit visibility mask for the independent shadow/color frusta. Records are grouped in mask order 1/3/7/5/4/6/2, giving each pass at most two contiguous ranges per mesh; adjacent ranges are merged. Every visible object occupies one slot in one upload, shared by all passes, with a hard 4,096-object union limit. Every submitted queue is consumed even when all its objects are culled, preventing geometry from leaking across world/portrait camera changes. An empty queue uploads no instances or shadow passes; its first flush still draws the pending sky. The render path never changes the simulation floor or obstacle map.

`BeginFrame` defers the sky until the first flush, so the current world camera and capture overrides are available. It draws once before world geometry or the portrait camera/viewport switch. The sky pass reuses the constant buffer's world slot for inverse view-projection; reconstructed world rays ignore camera translation and anchor clouds/horizon to view direction. Initialization supplies a valid default camera. Extra flushes, captures and portraits cannot redraw the sky over existing geometry. This retains one sky triangle/draw and adds no GPU allocation.

`visual::Frustum` prepares six planes and their normal lengths once per view during a flush, so object tests reuse them without rebuilding planes or taking square roots. Visibility classification also counts each mask; prefix offsets and a stable scatter replace seven rescans of each mesh queue. This preserves the previous instance order and range merging. Interface ovals, rings and scrollwork reuse fixed curve samples (728 bytes of sample data) while applying current position, scale and color every frame. No GPU resources, draw order, interaction hit regions or animation updates are cached or skipped by these optimizations.

Material RGBA channels now store albedo intensity, two signed height slopes and roughness. Startup generation uses periodic noise and wrapped central differences; GPU mip generation filters all channels together. The vertex shader emits metric object coordinates and scale-corrected local normals. Three triplanar samples blend each material, and screen derivatives reconstruct a bounded world-space surface gradient without tangent vertices. This anchors grain/relief to animated parts. Terrain paving adds shallow derivative-based relief while retaining the flat collision floor. Lighting uses linearized authored colors, roughness-controlled specular response, a highlight shoulder and display conversion; UI colors stay unchanged. Shadow comparison uses the geometric normal, independently of the perturbed shading normal. The valid receiver-gradient bound is 0.02 depth units per texel so grazing surfaces remain free of stripes under the new response. No texture, mesh, render-target or instance allocation was added.

Shadow casting is explicit (`visual::ShadowMode`) and stored in the existing 160-byte instance record. Opaque objects cast by default, regardless of material; grass, quest effects, lantern cores and `DrawMarkerBox` opt out. A two-layer 1024-square D32 array holds a fixed 62-unit whole-island projection and a 20-unit detail projection centered on the world camera target. `ShadowProjections` snaps the detail origin to whole light-space texels; extent, orientation and depth range remain fixed. Each depth pass uses independent light culling and a depth-only vertex shader. Both passes and the color pass share the bounded 4,096-record upload buffer.

The pixel shader selects coverage in shadow coordinates and smoothly blends the overlap. It computes both receiver-plane gradients before coverage-dependent branches, then makes 16 point comparisons with separable tent weights per sampled map (32 in the overlap). Each comparison uses the depth at its actual texel center, avoiding large global bias and bilinear edge scalloping. Bias/gradient limits protect grazing surfaces. Portrait lighting is independent: its camera cannot move either world projection, and its pass does not clear or write the shadow array. Both world layers are cleared when a queued world batch is processed, including a batch with no visible casters. An empty flush leaves the already-rendered maps intact. No scene-dependent shadow resources are allocated per frame.

`CharacterPose` uses a bounded two-bone solve to place elbows and knees without stretching limbs. `CharacterView` transforms those local joints into the world or portrait and attaches equipment to the hands. `Renderer::DrawMeshBetween` aligns any shared mesh along a segment with a facing vector; it adds no new per-actor geometry buffers. The new head, hair and boot meshes are startup resources. These are procedural part transforms, not skeletal skinning. `Game::ExecuteCommand` advances simulation and visual time/walk state together, so the hidden workload uses the same presentation step as normal input. Attack/windup state remains simulation-owned.

`animation::State` adds transient, bounded scalar channels per player/enemy: breathing/sway, movement lean, airborne blend, ascent/descent, landing compression and hit recoil. It reads successful travel, height/vertical speed, transient damage events and within-step landing information after simulation updates. Damage flags reset every update, including early returns, and never enter saves. Cosmetic hit tints decay independently, including after player defeat. The simulation solves ground contact analytically and supplies impact speed plus time since contact, so landing compression does not depend on when the next frame observes the floor. Airborne feet extend toward standing as height approaches zero; grounded landing changes hip height and solves bent knees against the existing ankle targets. Cubic height weighting eases the airborne blend at both ends; squared positive stride/ascent channels remove the sharp foot-lift and apex corners. Consecutive damage refreshes recoil while preserving its current amplitude. Death, restart, respawn, load and training-start reset the appropriate state. No channel changes root position, yaw, damage, collision, inventory or saves. `UpperPoint` and `UpperDirection` share the torso pivot across geometry, shoulder joints, clothing and equipment. NPC/portrait idle poses are pure functions of supplied visual time, so drawing extra views cannot advance motion. Walking still uses the existing gait, without world-space foot locking or skeletal clips.

`-BenchmarkSuite` / `--benchmark-suite` runs four in-memory scenarios: stationary HUD, walking/orbit, repeated combat/orbit, and merchant/character/bag. Setup and snapshot loads are excluded from frame timing; movement distance and observed windups/hits ensure active workloads. Reports distinguish CPU frame timing from asynchronous latest-ready GPU observations. This path never writes a player save, and does not replace visible interactive or long-session profiling.

`MediterraneanClient` is a separate static library shared by the executable and the interface integration test. Simulation remains platform-independent. The Escape menu captures commands without bypassing `Simulation::Update`; focus-loss suspension remains an Engine responsibility. Character and bag have independent open states, with the central overlay stored separately. Reverse-ordered hit regions consume covered window surfaces; mouse orbit is suppressed over windows and during item dragging while keyboard movement stays available for the side panels. Item UI actions emit validated inventory/potion commands against the one simulation-owned inventory. Pointer release ends a drag; focus, window/display changes and panel closing cancel it. Both character render paths build their outfit from worn slots.

The renderer batches alpha-blended UI geometry and rasterizes the installed Windows font into a small atlas. Character previews temporarily use a bounded viewport and studio lighting, then restore world camera/viewport state. The illustrated map is generated once from world data. See [interface.md](interface.md) for controls, resources, reference sources and test coverage.

The merchant occupies a separate central panel while retaining independent character/bag states. Its buttons use simulation availability, and side-window item operations remain usable. E closes it without also sending an interaction that would reopen it. The counter is shared solid map data for rendering, camera collision, navigation and the atlas. Helmet/shield presentation uses the same worn-slot mapping in the world and portrait.
